Handoff — Thread-Tracker HTML Escaping THEME-SIDE

For: the agent scoped to the JCink forum theme / wrapper code  ·  From: Watcher (JCink Analytics API) side  ·  Date: 2026-05-16  ·  Scope: theme JavaScript only — no Watcher/API changes required for this task

TL;DR. The theme’s thread-tracker builds its tab markup by interpolating raw string values from the Watcher API (forum names, thread titles, last-poster names, post excerpts) into HTML. None of it is HTML-escaped. When any of those strings contains ", ', <, >, or &, the generated markup breaks and the entire threads tab renders empty for that user. This was first hit by member 263 (Xu Xialing). The fix is to treat every API string as untrusted and escape it (or build the DOM via createElement/ textContent) before it touches the page. This is independent defense-in-depth and must be done even though a related data-cleanup is shipping on the Watcher side — see “Scope & coordination” at the end.

1. Background — what breaks and who sees it

The theme renders a per-character “threads” tracker by calling the Watcher REST API and building tab content from the JSON response. For member 263 (Xu Xialing, showuser=263) the tab shows up completely empty, even though the API returns 5 valid threads for her. Only this user (and any user whose data contains a triggering character) is affected, which is what is currently blocking broad rollout of the new theme. The forum’s legitimate data is fine; the breakage is purely in how the theme JS turns the JSON into HTML.

2. Root cause (theme-side)

The tracker JS builds an HTML string (or sets innerHTML) by concatenating API field values directly into attributes and element bodies, e.g. something equivalent to: 

html += '<span class="forum" title="' + t.forum_name + '">' + t.forum_name + '</span>';
// or an inline handler: onclick="open('" + t.url + "')"

When a value contains the same quote character used to delimit the attribute (or </& in element text, or a quote inside an inline JS handler), the parser desynchronizes:

  • A double quote in a "-delimited attribute terminates the attribute early and corrupts the rest of the tag — if the whole tab is one concatenated innerHTML string, the mis-nesting swallows or hides the following rows and the tab collapses to empty.
  • A quote inside an inline on* handler / template literal is a JavaScript syntax error that aborts the entire render — nothing draws at all.

3. Why only some users trip it

Trigger characterAppears inBreaks
" (double quote)forum names, thread titles double-quoted HTML attributes (the common build pattern)
' (apostrophe)post excerpts (“don’t”, “you’ve”, “let’s”), titles, names single-quoted attributes / inline JS string literals
< > & any free-text field (titles, excerpts, names) element text / starts a bogus tag / mangled entity

Most characters happen to have only “clean” data, so they render. Xu Xialing has a thread in a forum whose name contains " characters, so her tab is the first to break. Apostrophe-laden excerpts are extremely common, so a single-quote build pattern would break almost everyone — meaning the current pattern is double-quote based and any " in the data is the immediate poison. The correct fix is general: treat all of these characters in all string fields.

5. The required fix

Option A (preferred): build the DOM, never concatenate HTML. The DOM API escapes for you — textContent and setAttribute cannot break out of their context. This eliminates the entire bug class permanently.
function buildThreadRow(t) {
  var row = document.createElement('div');
  row.className = 'wt-thread';

  var a = document.createElement('a');
  a.textContent = t.title;                 // safe: text node, no parsing
  if (/^https:\/\//.test(t.url)) a.href = t.url;   // scheme-checked
  a.target = '_blank';
  a.rel = 'noopener';
  row.appendChild(a);

  var forum = document.createElement('span');
  forum.className = 'wt-forum';
  forum.textContent = t.forum_name;        // safe even if it contains " ' < &
  row.appendChild(forum);

  var poster = document.createElement('span');
  poster.className = 'wt-last';
  poster.textContent = (t.last_poster_name || '') + ' — ' + (t.last_post_date || '');
  row.appendChild(poster);

  return row;                              // append to the tab container
}

// Render:
['ongoing','comms','complete','incomplete'].forEach(function(cat){
  var container = document.getElementById('wt-' + cat);
  container.textContent = '';              // clear without innerHTML
  (data[cat] || []).forEach(function(t){ container.appendChild(buildThreadRow(t)); });
});
Option B (only if a string-template approach is mandatory): route every interpolated value through an escaper. This is more fragile — prefer Option A.
function esc(s){
  return String(s == null ? '' : s).replace(/[&<>"']/g, function(c){
    return {'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[c];
  });
}
// Every field, every time. Quote ALL attributes. Never put data in
// an unquoted attribute, in an inline on* handler, in <script>, or in a
// javascript:/data: URL.
html += '<a class="wt-t" href="' + esc(t.url) + '">' + esc(t.title) + '</a>'
      + '<span class="wt-f">' + esc(t.forum_name) + '</span>';

Hard rules (apply regardless of option)

  • No untrusted value in an inline event handler (onclick="…") — attach listeners with addEventListener and read data from dataset instead.
  • No untrusted value in a URL attribute without verifying it begins with https:// (or your allowed host) — blocks javascript: injection.
  • Quote all HTML attributes if you do build strings.
  • Wrap the whole render in try/catch and, on error, show a small “tracker failed to load” message rather than letting one bad row blank the tab silently — fail visible, not empty.

6. Acceptance criteria / how to verify

  1. Locate the code: in the wrapper, find the JS that does fetch(…/api/character/…/threads) (or WatcherAPI) and builds the threads tab. For orientation, the Watcher webhook integration JS lives in the same wrapper around lines ~22297–22328; the tracker render is a separate block — search for /threads, ongoing, or the tab container IDs.
  2. Repro before fix: as the logged-in WATCHER account (only it sees the new theme), open therewasanidea.jcink.net/index.php?showuser=263 with DevTools open. Console shows an HTML-parse-mangled tracker or a JS error at the row build; the threads tab is empty.
  3. After fix, the tab populates for member 263 with all 5 threads (3 ongoing, 2 incomplete), and the forum label renders literally as "The Third Ring" (quotes shown as text, not breaking layout).
  4. Adversarial check: confirm a thread whose last_post_excerpt contains apostrophes (“don’t”, “let’s”) and one whose title/forum contains ", <, or & all render as plain visible text with no layout break and no console error.
  5. Regression: spot-check 2–3 other members’ trackers still render identically.

7. Scope & coordination (read this)

A separate Watcher-side Merge Request (fix/acp-double-quoted-forum-names, bumps APP_VERSION 2.6.6) fixes the specific reason forum 94’s name arrived with literal quotes (a SQL-dump parsing bug). Do not treat that as a substitute for this theme fix. The API will always be able to return ", ', <, >, & in titles, names, and excerpts because members type those characters. The theme must be robust to any string. The two fixes are independent: the Watcher MR removes one current trigger; this task removes the entire vulnerability class. Ship this regardless of MR status, and do not assume the payload is pre-sanitized.
